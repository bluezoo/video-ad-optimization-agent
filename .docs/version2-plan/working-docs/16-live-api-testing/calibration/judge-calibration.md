**Model:** `gemini-3.6-flash` (config.MODEL) — Vertex AI, `GOOGLE_CLOUD_LOCATION=global`, structured JSON output via `response_schema`.
**Judge module:** `tests/live/judge.py`. **Tests:** `tests/live/test_media_judge.py`.
**Run date:** 2026-07-23 (live, single pass over the media already on disk from Tasks 12-13, plus one freshly rendered RPI chart).
**Video input mode:** both videos judged via **direct mp4 bytes** (`types.Part.from_bytes(mime_type="video/mp4")`). The API accepted the ~1-2 MB mp4s with no size/format refusal, so the 4-sampled-frames fallback (`judge._sample_frames`, ffmpeg) was NOT exercised this run — it remains in place as a safety net.

Every media item is judged against a rubric **derived from the generator's own source** so judge and generator cannot silently drift: the subject expectation comes from `app/tools/prompt_archetypes.py` (`wearable` = human model wearing the garment; all other archetypes = product-hero, no humans), and the no-text policy from `app/tools/prompt_builders.py`'s `_NO_TEXT_BLOCK`/`_AUDIO_BLOCK` (owner ws09 directive: music-only, clean frame, the only allowed text is text physically on the product's own packaging).

**Honesty bound:** the judge reviews **pixels only**. For videos it checks visible frames for burned-in captions; it does **not** verify audio. The rubric text says so explicitly — "music-only / no-voiceover" is enforced by the prompt policy, not observed here.

## Proposed hard/warn severity mapping (for the OWNER GATE)

This is the phase-doc open-question-1 default, carried into the code as `judge._IMAGE_SEVERITY` / `_VIDEO_SEVERITY` / `_CHART_SEVERITY`. **Not yet owner-pinned** — the controller presents these verdicts + the media paths at the gate; the owner ratifies the split, and only then does Task 16 amend `99-open-questions.md`.

Ad creatives (images + videos):

| Check | Proposed severity | Rationale |
|---|---|---|
| `subject_matches_archetype` | **hard** | Wrong subject (human in a product-hero ad, or no model in a wearable ad) is a policy-defining failure — the archetype is the contract. |
| `no_rendered_text` | **hard** | The ws09 owner directive is absolute: no rendered text/graphics beyond the product's own packaging. |
| `no_captions_any_frame` (video only) | **hard** | Same directive, applied across every visible frame — burned-in captions violate the clean-frame policy. |
| `setting_mood_plausible` | **warn** | Subjective fit-to-brief; a plausibility miss is a quality nudge, not a hard contract breach. Flagging (not failing) keeps the tier from going red on a defensible aesthetic call. |

RPI comparison chart (INVERTED rubric — a chart is a data viz, text is REQUIRED):

| Check | Proposed severity | Rationale |
|---|---|---|
| `axes_and_labels_legible` | **hard** | A chart with missing/illegible axes, labels, or value tags is unusable as evidence. |
| `correct_creative_count` | **hard** | Bar count must equal the seeded activated-creative count (3 for campaign 1) — a wrong count means the deterministic data→chart mapping broke. |

## Notes / limitations observed

- **No negative controls this run.** Every item is policy-conformant media, so every check passed — this validates the judge doesn't false-positive on good media, but does NOT prove it catches violations. Deliberate-break confidence for the judge is deferred (a text-injected image or a human-in-product-hero shot would be the negative control); flagged for the owner gate / Task 16 docs if the owner wants a stricter sign-off.
- **Determinism:** gemini-3.6-flash multimodal verdicts are LLM outputs and may vary run-to-run on borderline cases; the hard checks here (subject presence, rendered text, bar count) are unambiguous on this media, so re-runs are expected stable. Borderline `setting_mood_plausible` is warn precisely because it is the least deterministic.
- **Cost/wall time:** 6 multimodal judge calls (2 video + 4 image) completed in one pass; full timing is captured by Task 16's docs during the full `make test-live` run (not run here — this dispatch is pre-gate only).
