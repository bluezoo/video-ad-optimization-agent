## Implementation approach

**Storage seam shape — the one genuine design choice:**

- **Option A (chosen) — extend `app/storage.py` in place.** Keep its existing per-function `get_storage_mode()` branching, add the missing halves: a `save_product_image()` + local branches for the three product-image functions (configurable local assets dir), existence-checked URL helpers, and route the four URL-emitting tools plus video_tools' hand-rolled writes through it. Rationale: the module already IS the seam — two backends, functions in place, GCS lazy; finishing it matches the repo's don't-overcomplicate philosophy, and the diff stays reviewable.
- **Option B (rejected) — a `StorageBackend` ABC** (mirror of ws11a's audience seam): clean but unnecessary — unlike audience data (a real future live conformer), storage has exactly two backends both fully known today; an ABC adds a layer with no third implementer in any phase doc.
- **Option C (rejected) — leave storage.py, wrap it in a new module:** two places to look for the same responsibility; the raise-sites and personal-bucket default would survive inside the old module.

### Shape of the work

1. **Local-first `app/storage.py`:**
   - Delete `DEFAULT_GCS_BUCKET` (config.py:72-73) — `GCS_BUCKET` unset ⇒ local mode, set ⇒ GCS opt-in. New `LOCAL_ASSETS_DIR` config (env-overridable; default `<repo>/local_assets/`) with subdirs mirroring the GCS prefixes (`product-images/`, `generated/`, `seed-images/`).
   - Add `save_product_image(filename, data)`; give `product_image_exists`/`read_product_image`/`get_product_image_path` local branches (the three raise-sites become the GCS-branch-only path).
   - URL policy: `get_public_url`-family gains existence checking in GCS mode and returns `None` in local mode (today's graceful-omission behavior). Tools emitting URLs switch to a shared helper returning `{image_url?}` or `{image_status: "stored locally"| "missing"}` — never an unchecked `storage.googleapis.com` link, never a raw local path dressed up as a URL. Rendering of generated media stays on the ADK-artifact channel (already how video + charts reach the browser).
   - Route all four URL surfaces (list_products, get_video_review_table, get_video_details, maps_tools) through it; replace video_tools' hand-rolled local writes with `storage.save_video`/thumbnail equivalents; fix image_tools.py:270's raw env read; scrub the mock_data.py:77 comment (validation grep: zero `kaggle-on-gcp` hits).
2. **Gated seeding:** `DEMO_DATASET` env (`fashion` default | `none`; invalid → ValueError at config load, mirroring APP_MODE's style; demo-scoped selector — amend the config.py "only mode knob" comment accordingly). agent.py replaces `init_database(); populate_mock_data()` with a `seed_demo_data()` gate: schema init always; product+campaign seeding only when `DEMO_DATASET=fashion` (preserving today's full behavior: 22 fashion + 6 retail core + demo campaigns) **and** idempotently (existing count guards). `none` ⇒ schema only, empty catalog. The two `init_database()`-internal seeding calls (db.py:259-261) relocate into the gate (per the DISCOVERY).
3. **Onboarding tools** (`app/tools/onboarding_tools.py`, wired to the **Campaign agent** per the phase doc's recorded owner decision; the Media-agent alternative was considered for co-location with `list_products` and rejected — onboarding is campaign-setup activity, and instruction text cross-references browsing):
   - `create_product(name, category, description, attributes)` → `insert_product`; image_filename gets a deterministic slug placeholder + `image_status: "pending"` until upload/generation fills it; duplicate names translate to the status/message error convention.
   - `import_products_from_folder(folder_path)` → filename/subfolder conventions → products + `save_product_image` through the seam; common formats accepted, tiny images warned not blocked (doc 15 open question 1's default).
   - `generate_product_image(product_name_or_id, style_hint?)` → `model=IMAGE_GENERATION` via `generate_scene_image`'s call pattern, **simple category-aware product-photography prompt** (clean neutral-background reference shot; NOT wired through `resolve_archetype()` — that system governs creative scenes, a reference photo needs no variation machinery; ws09's extension point stays available and this decision is recorded here). Stores via the seam, updates the product row, clears "pending".
   - Every product presented as browse-ready has a real stored image or an explicit pending status (ws08 amendment's guarantee).
4. **CLI wrapper:** `scripts/onboard_products.py` in the repo's bare-script style, calling the same functions (parity-tested, no logic drift).
5. **Drive bundle (donor design, localized):** `scripts/demo_assets.py` — gdown download by `DEMO_ASSETS_DRIVE_ID` (config/env; unset ⇒ graceful "bundle not configured" skip), zip extract, sha256-map `manifest.json` verification, idempotent state marker, installing into `LOCAL_ASSETS_DIR` — **no GCS anywhere**. Plus a builder mode producing the zip+manifest from a local asset directory, so the owner can assemble the bundle (source images currently live only in the personal GCS bucket — pulling them and uploading the zip to Drive is an owner step, documented in SETUP_INSTRUCTIONS). `gdown` added to requirements (net-new dependency, flagged).
6. **Scenario + guides:** `docs/demo-scenarios/from-scratch-onboarding.md` (fashion.md conventions: Scenario/Scene, named expected tool calls, Pass/Fail) covering `DEMO_DATASET=none` → conversational onboarding → campaign → video → RPI analytics; root `DEMO_GUIDE.md` "Workstream Testing Journeys" gets the ws15 journeys; SETUP_INSTRUCTIONS gains the local-first section (.env landmine: existing dev `.env`s carrying `GCS_BUCKET` keep GCS mode until edited).
